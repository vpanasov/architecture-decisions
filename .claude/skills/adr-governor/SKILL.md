# ADR Governor Skill

## When to use
- Command "generate adr from RFC-XXXX"

## How it works
1. Read RFC-XXXX from https://bz.incdb.team/display/DOCS/RFCs
2. Check RFC-XXXX status = Approved. If not, abort with a message.
3. Save RFC-XXXX content to rfcs/RFC-XXXX.md (with attached images to rfcs/images/)
4. Check if an ADR for RFC-XXXX already exists in adrs/. If yes, abort with a message.
5. Determine ADR-XXXX number: max(existing ADRs) + 1.
6. Run scripts/extract_rfc.py:
	- Extract from RFC-XXXX: title, context, decision, alternatives, consequences, tech debt, metrics
7. Rewrite each extracted field in plain, non-technical language for a broad audience (not just engineers):
	- Keep only the essence of the decision — what was decided and why, in terms a non-technical reader understands.
	- Drop implementation-level detail: protocol/standard names, config keys, exact thresholds/TTLs/SLOs, ticket links, code identifiers, vendor/library names used only for justification. A reader who needs this detail follows the RFC-XXXX link.
	- Do not invent or change the decision itself — only reword/compress what RFC-XXXX already says.
8. Generate ADR-XXXX using the template templates/adr-template.md
  - Preserve the template's structure and bold lead-in keywords exactly (**В контексте**, **сталкиваясь с**, **мы решили**, **и отказались от**, **чтобы достичь**, **принимая**, References) — never restructure into headers/bullet lists.
  - Wherever technical detail was trimmed (typically in "мы решили" and "принимая"), add a pointer to RFC-XXXX for full detail.
  - Set ADR-XXXX Status = Accepted
9. Write ADR-XXXX to adrs/ADR-XXXX-<name>.md

## Scripts
- extract_rfc.py: Extract data from RFC-XXXX (outputs JSON to stdout)

## Templates
- templates/adr-template.md

## Constraints
- Only process RFC-XXXX with Approved status
- Always include "Generated by: AI agent (adr-governor)" in ADR-XXXX metadata
- ADR-XXXX must reflect only the essence of the decision, readable by a broad (non-technical) audience — no technical implementation details. Full detail lives in RFC-XXXX and is reachable via the References link.
- Never restructure or reorder the ADR's fixed sections/bold keywords — only the prose inside each clause is rewritten
- Leave all dates in ADR (Date accepted, Date implemented) empty — filled in manually
- All links in References must be active and point to source pages in Confluence (https://bz.incdb.team/...)
