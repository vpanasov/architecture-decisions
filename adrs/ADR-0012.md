**Дата принятия**:

**Дата внедрения**:

**Статус:** Accepted

# Decision

**В контексте** корпоративного использования LLM (ChatGPT, Claude) сотрудниками Life Pay для рабочих задач и необходимости вывода решения из пилотного `analytics` tenant в Production на единой PSP-Cloud-платформе,

**сталкиваясь с** утечкой персональных данных клиентов (ФИО, номера карт, паспортные и платёжные данные) во внешние LLM-API через личные аккаунты сотрудников; отсутствием учёта расходов на токены и бюджетных лимитов; операционным хаосом из-за отсутствия единой точки входа; а также невыполнением корпоративного требования compliance unification о переводе всех продуктов на единую PSP-Cloud-платформу,

**мы решили** вывести LLM Gateway в Production на shared PSP-Cloud-платформе Life Pay (Yandex Managed K8s, кластер `PSP-Cloud-prod`, namespace `llm-gateway-prod`), мигрировав данные с текущего prod в `analytics` tenant; прикладная логика (Open WebUI → PII Masker → LiteLLM + skill-runtime) переносится без изменений; меняется инфраструктурный слой: ArgoCD → umbrella CI Life Pay, k8s Secret → HashiCorp Vault, kube-prometheus → платформенный мониторинг; egress к внешним LLM-провайдерам сохраняется через корпоративный forward-proxy; обезличивание ПД обеспечивается PII Masker (Microsoft Presidio + SpaCy + 19 кастомных распознавателей российских документов) на egress и async sweeper'ом истории в БД,

**и отказались от** корпоративного аккаунта ChatGPT/Claude (не закрывает главный риск утечки ПД); локальной LLM на Ollama + Llama/Mistral (неприемлемое качество и стоимость GPU); Azure OpenAI / Yandex GPT (нет нужных моделей, медленный выход); варианта остаться в `analytics` tenant (противоречит корпоративному требованию о единой PSP-Cloud-платформе); варианта «ничего не делать» (неприемлемый риск по 152-ФЗ),

**чтобы достичь** нулевого количества инцидентов передачи необезличенных ПД во внешние API; 100% прохождения исходящих запросов через обезличивание (PII Masker — обязательное звено); доступности сервиса на уровне SLA платформы PSP-Cloud; контроля расходов на LLM через бюджетные лимиты (soft $40/мес на пользователя + жёсткий лимит Opus 15 запросов/нед); перевода стихийного использования личных аккаунтов в контролируемый корпоративный периметр; соответствия требованиям 152-ФЗ и compliance unification,

**принимая** короткое окно (~10 сек) наличия оригинального промпта с ПД в БД до срабатывания фонового sweeper'а (полное отсутствие оригинала возможно только через форк Open WebUI — нецелесообразно); исключение для юр-отдела — чаты с моделью `no-mask-assistant` не sweep'ятся (осознанная бизнес-необходимость, двойной гейт: allowlist пользователей + белый список моделей); остаточный риск NER-обезличивания, которое по природе технологии не гарантирует 100% recall на нетипичных формулировках (митигируется расширяемым набором распознавателей, gold-датасетом и мониторингом); Open WebUI как SPOF (1 replica, локальный state, upstream не поддерживает multi-replica — при падении UI недоступен ~1–2 мин); управляемый технический долг: CVE в образе pii-masker (~1 день на устранение) и отсутствие retention-policy для uploads в S3 (~0.5 дня).
