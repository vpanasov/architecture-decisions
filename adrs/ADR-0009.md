# ADR-0009: Интеграция Pyrus и Correct для распознавания документов

# Decision

**В контексте** автоматизации сквозных финансовых процессов в Pyrus, связанных с обработкой счетов, платёжных поручений и закрывающих документов,

**сталкиваясь с** ручным переносом информации из счетов в платёжные поручения (1С:Бухгалтерия), ручной отправкой закрывающих документов из ЭДО (Диадок) инициаторам и ручным заполнением заявок в Pyrus данными, которые уже содержатся в первичных документах,

**мы решили** использовать SaaS-сервис распознавания документов на базе ИИ — Correct, интегрированный через нативное расширение в Pyrus, для автоматического извлечения данных из счетов, актов, УПД и счетов-фактур; взаимодействие с 1С строится через интеграционный шлюз n8n (ADR-0008),

**и отказались от** самостоятельной разработки алгоритмов распознавания (отсутствует ресурс у команды процессного офиса), варианта «ничего не делать» (не будет выполнено требование бизнес-заказчика по максимальному сокращению ручных операций, при этом компания продолжает платить подрядчику «ПФМ24» за автоматизацию процесса) и альтернативных сервисов (Beorg, Smart Engines, СБИС) — у Pyrus нет встроенной интеграции с ними,

**чтобы достичь** сокращения ручных операций бухгалтерии, ускорения обработки ~150 заявок на оплату в месяц, автоматического сопоставления закрывающих документов с заявками без вовлечения бухгалтерии,

**принимая** передачу коммерческой информации (финансовые документы компании) третьей стороне — SaaS-сервису Correct — как компромисс между безопасностью и стоимостью разработки собственного решения.
