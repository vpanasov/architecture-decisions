# ADR-0011: rf bypass – gateway доступа к зарубежным ресурсам, заблокированным по GeoIP

> Сгенерирован: AI-агент (adr-governor)

**Дата принятия**: 2026-06-29

**Дата внедрения**: 2026-05-20

**Статус:** Implemented

---

# Decision

**В контексте** обеспечения доступа команд разработки к зарубежным сервисам (AI-провайдеры, репозитории пакетов, SaaS-инструменты), заблокированным по GeoIP для клиентов с IP-адресами из России,

**сталкиваясь с** отсутствием централизованного управляемого решения — сотрудники использовали разрозненные персональные VPN/прокси, что приводило к неконтролируемому egress, отсутствию аудита, нестабильности доступа, дублированию настроек на каждом рабочем месте и риску утечки нецелевого трафика во внешние сервисы,

**мы решили** развернуть централизованный слой rf bypass — RU-узлы с forward-прокси (Envoy) внутри инфраструктуры PSP (Yandex Cloud), зашифрованные обфусцированные каналы (WireGuard + Cloak) до exit-узлов за пределами РФ, с автоматической раздачей конфигурации клиентам через PAC/WPAD; прокси выпускает только трафик на домены из allowlist'а, а для произвольного IP-трафика (приложения без поддержки прокси, AWS VPN-эндпоинты) используется GRE-транспорт через VPN-концентратор,

**и отказались от** персональных VPN/прокси на каждом рабочем месте (неконтролируемый egress, нет аудита, не масштабируется); коммерческого VPN-сервиса на всю организацию (выпускает весь трафик, зависимость от провайдера, риски compliance); прямого прокси без обфускации (уязвим к DPI-блокировке WireGuard-handshake); варианта «ничего не делать» (потеря производительности команд, теневой egress),

**чтобы достичь** управляемого, прозрачного для пользователя доступа к geoblock-ресурсам с единым allowlist'ом доменов; централизованного контроля и аудита egress-трафика; автоконфигурации клиентов (PAC/WPAD) без ручной настройки на каждом рабочем месте; отказоустойчивости через active-standby RU-узлы и резервные exit-узлы в разных юрисдикциях; устойчивости канала к DPI через сменяемый слой обфускации,

**принимая** хранение ключей в git (компромисс ради операционной простоты, требует контроля доступа и ротации); зависимость от арендованных exit-VPS без SLA (митигируется резервными узлами и быстрым добавлением через Ansible); отсутствие фильтрации allowlist'ом в GRE-режиме (ответственность на стороне VPN-концентратора); непокрытие класса трафика терминалов и голосовых сервисов (VLESS-решение пока не в prod); отсутствие сводного дашборда статусов exit-узлов; негарантированную стабильность GeoIP-обхода при ужесточении детектирования удалёнными сервисами; необходимость ручного сопровождения allowlist'а.
